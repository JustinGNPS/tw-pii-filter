為什麼需要這個

現有隱私防護工具對台灣個資幾乎無法偵測 —— 這是我們實測出來的數字，不是推論。

數值為 recall（召回率）。測試語料為 300 筆合成台灣個資，涵蓋醫療對話、履歷、客服記錄三種情境， 全數為假資料；每個身分證與統編各生成「檢核碼正確」與「錯誤」兩版。固定 random seed、鎖定套件版本。
關鍵解讀：LLM Guard 在人名與地址上達到滿分 1.000，同一次執行卻在身分證上掛零 —— 不是中文能力不足，是設計裡從來沒有台灣。而且沒有任何一個現有工具驗證檢核碼。

系統怎麼運作

語言模型判斷「像不像」，檢核碼判斷「是不是」—— 個資防護兩者都需要。

L1 規則驗證層身分證、統編、健保卡號的檢核碼演算法，確定性判定
L2 語意偵測層本地 NER 小模型處理人名、地址、機構等上下文實體
L3 組合風險評分偵測準識別子共現，估算再識別風險並提出警示
還原AI 回覆時依固定格式把佔位符換回真值，使用者無感

兩個載體，一個核心

瀏覽器擴充（面向一般使用者）

選取文字按右鍵「隱私處理後貼上」，貼進 ChatGPT 的已經是遮蔽後的內容。 側邊面板即時顯示偵測到什麼、風險多少。TypeScript 實作。

API Proxy（面向開發者）

攔在 AI coding agent 與雲端 LLM 之間。Agent 讀到 .env 或客戶名單時自動攔下， 回覆時自動還原，工作流程完全不變。Python 實作。

我們知道自己的限制

  • 關聯性洩漏（刻意取捨）：「[NAME_1] 的電話是 [TW_PHONE_M_1]」這個關聯本身仍然保留。 要讓 AI 還能正常做事，就不能把結構也打碎。
  • 組合風險只提示、不強制遮蔽：由使用者判斷。過度遮蔽會讓 AI 無法作答。
  • 計數是「不重複字面值」不是「不重複當事人」：同一張身分證的全形與半形寫法會拿到兩個佔位符， 因為還原時必須知道原本是哪種寫法 —— 統一正規化等於偷改使用者原文。
  • 這個展示頁只跑規則層（L1）：語意層需要下載 NER 模型，不適合放在網頁裡。 人名、地址的偵測請用完整版。
