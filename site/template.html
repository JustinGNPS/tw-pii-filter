為什麼需要這個

現有工具對台灣個資幾乎偵測不到，而且沒有任何一個會驗證檢核碼。

LLM Guard 在人名與地址拿到滿分，同一次執行卻在身分證上掛零 —— 不是中文能力不足，是設計裡從來沒有台灣。

這些數字怎麼測的

測試語料為 300 筆合成台灣個資，涵蓋醫療對話、履歷、客服記錄三種情境，全數為假資料； 每個身分證與統編各生成「檢核碼正確」與「錯誤」兩版。固定 random seed、鎖定套件版本。

怎麼運作

語言模型判斷「像不像」，檢核碼判斷「是不是」。一個偵測核心，兩種使用方式。

L1 規則驗證身分證、統編、健保卡號的檢核碼演算法，確定性判定
L2 語意偵測本地 NER 模型處理人名、地址這類沒有固定格式的實體
L3 組合風險年齡、居住地、職稱同時出現時估算再識別風險
還原AI 回覆時把佔位符換回真值，使用者無感

給一般使用者。在 ChatGPT 這類網站的輸入框按右鍵「隱私處理後貼上」，貼進去的已經是遮蔽後的內容。 只需要 Chrome 或 Edge，不用裝 Python。

怎麼導入（以 Aider 為例） 
# 1. 啟動本地 proxy（Python 3.11）
.venv\Scripts\python.exe -m uvicorn proxy.main:app --port 8010

# 2. 讓 agent 指向它
set OPENAI_API_BASE=http://127.0.0.1:8010/v1

# 3. 照常使用
aider

其他 agent 只差在怎麼告訴它 base URL 換了；遮蔽與還原的邏輯完全共用，不是六套程式。

選配。人名與地址沒有固定格式，要靠本地 NER 模型。開啟後需另外下載約 400 MB 的模型權重， 之後離線推論；預設關閉，關閉時完全不會載入相關套件。

已知限制

  • 關聯性仍然保留。「[NAME_1] 的電話是 [TW_PHONE_M_1]」這個關聯不會被打碎，否則 AI 無法正常作答。
  • 組合風險只提示、不強制遮蔽。過度遮蔽會讓 AI 無法作答，由使用者判斷。
  • 計數是不重複的字面值，不是當事人。同一張身分證的全形與半形寫法會拿到兩個佔位符，還原時才能換回原本的寫法。
  • 這一頁只跑規則層與組合風險。人名、地址的偵測需要語意層，請用完整版。
