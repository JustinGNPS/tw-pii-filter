    這個專案在做什麼

    資料送往雲端 AI 之前，在本地完成台灣個資的偵測與可逆遮蔽；AI 回覆時自動換回真值。使用者全程無感，雲端全程看不到真資料。

    補的缺口：Presidio / GLiNER / LLM Guard 這些國外工具對台灣身分證、統編的偵測率是 0.000，而且沒有任何一套會驗證檢核碼。

    四層偵測核心 一個核心，兩個載體共用

    層誰做做什麼特性
    Layer 1
    規則層    		A正則找出格式符合的字串，再用檢核碼演算法驗證真偽。8 種型別：TW_ID / TW_TAX / TW_NHI / TW_PHONE_M / TW_PHONE_L / EMAIL / CREDIT_CARD / API_KEY確定性 幾乎不漏
    Layer 2
    語意層    		D中文 BERT NER 判斷姓名、地址、公司、職稱 —— 這些沒有檢核碼可驗，也沒有固定格式機率性 recall 97.6%
    Layer 3
    組合風險    		D「沒有一個欄位是個資、組合起來卻指得到人」的情況評分並給泛化建議只提示 不遮蔽
    Layer 4
    重疊仲裁    		A兩層結果打架時擇一，保證回傳的範圍互不重疊下游地基

    Layer 4 在遮蔽之前（座標重疊會把文字切爛）；Layer 3 在遮蔽之後（要算的是 AI 實際看得到的殘餘風險）。

    兩個載體 攔的位置不同，面向的人不同

    載體誰做攔在哪面向狀態
    瀏覽器擴充C你在 ChatGPT 輸入框按 Ctrl+V 的那一刻一般使用者可用
    API ProxyBAI coding agent 送出 API 請求的那一刻開發者可用

    完整運作流程 以 agent 走 proxy 為例

    你的機器你叫 agent 幫你改一份含客戶資料的程式碼
    agent讀檔，把內容組成 API 請求送出（base URL 指向 proxy）
    proxy 攔截從 payload 裡挖出所有該掃的欄位（不同協定放的位置不同）
    偵測Layer 1 + Layer 2 各自掃 → Layer 4 仲裁 → 得到互不重疊的位置清單
    遮蔽從後往前替換成佔位符，同一真值配同一號碼，記進對照表
    評分Layer 3 對遮蔽後的內容評分，超過門檻印警示（不動內容）
    雲端 AI收到的、算出的、回覆的，全都是佔位符
    還原回覆是逐字串流的，佔位符可能被切在兩個封包之間 —— 緩衝處理後換回真值
    你看到的跟沒裝過濾器時完全一樣

    三條使用路徑的操作流程

    路徑一：AI coding agent 走 proxy

    1. 在 .env 設定上游端點與金鑰
   UPSTREAM_BASE_URL=https://your-llm-gateway/v1
   UPSTREAM_API_KEY=...

2. 啟動 proxy
   .venv\Scripts\python.exe -m uvicorn proxy.main:app --port 8010

3. 把 agent 的 base URL 指過來
   Aider       OPENAI_API_BASE=http://localhost:8010/v1
   Codex       config.toml 自訂 provider（wire_api = "responses"）
   Claude Code ANTHROPIC_BASE_URL=http://localhost:8010

4. 確認流量真的走了 proxy
   看到「第一個請求已抵達 proxy」這一行才算數

    實測通過：Aider、OpenCode、Continue、Cline、Codex、Claude Code。Cursor 攔不到（走自家後端，沒有自訂位址欄位），誠實列為不支援。

    路徑二：瀏覽器擴充

    cd extension
npm install
npm run build
→ chrome://extensions → 開發人員模式 → 載入未封裝項目 → 選 extension/dist

    之後在 ChatGPT / Claude / Gemini 貼上含個資的文字會跳出確認面板。

    路徑三：開啟語意層（姓名、地址）

    .venv\Scripts\python.exe -m pip install -r core/ner/requirements.txt
set PII_ENABLE_NER=1

    模型約 389 MB，第一次會下載，之後完全離線運作。這一點很重要：如果語意判斷要送雲端，整個專案就自我矛盾了。

    面向一般使用者：不用裝 Python、不用開終端機，裝上擴充之後照常用 ChatGPT，貼上含個資的文字時會跳出確認面板。

    為什麼主要入口是「貼上」而不是右鍵選單

    規劃書原本設定右鍵選單為主，實作時改成攔截 paste 事件，兩個理由：

    • 權限：右鍵選單拿不到剪貼簿內容，得額外要 clipboardRead 權限 —— 上架審查會被追問，也讓「最小權限」的訴求打折。攔截 paste 用 event.clipboardData，不需要任何額外權限。
    • 體驗：真正危險的情境是「沒多想就 Ctrl+V」，而右鍵選單保護不到沒多想的人。攔截 paste 讓使用者照常操作就被保護，零學習成本。

    右鍵選單保留為次要入口，處理已經打在輸入框裡的文字。

    技術上最特別的一件事：跨語言一致性

    瀏覽器裡跑不了 Python，所以規則層有一份TypeScript 重寫版（extension/src/core/）。兩套實作必須對同一份輸入給出相同結果 —— 否則同一段文字在擴充裡被遮、在 proxy 裡沒被遮，使用者無所適從。

    測試檔在驗什麼
    parity.test.ts兩套實作結果一致
    known_divergence.test.ts誠實記錄目前已知不一致的地方 —— 不是假裝沒有
    placeholder.test.ts佔位符格式與編號規則
    latency.test.ts貼上時的延遲

    怎麼看這些數字

    • agent 流量 —— 用來確認「流量真的有走 proxy」。設定沒生效時 agent 會安靜地直連雲端，畫面上不會有任何提示，這個數字停在 0 就是唯一線索。
    • 對照表（實際） —— agent 正在用的那張表裡有幾個不重複的真值。閒置 30 分鐘會自動清空。
    • 偵測快取 —— agent 每輪都重送整段歷史，同一份內容會被重複掃十幾次。命中率越高代表省下越多重複運算。
    • 語意層 —— 未啟用時姓名與地址不會被偵測到，這是預期行為。
