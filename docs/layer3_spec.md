# Layer 3：組合風險評分規格

## 目的

偵測「沒有直接 PII 字串，但多個屬性組合起來能定位到特定個人」的情況。
例如「32歲、住新竹、記憶體測試工程師」——每個屬性單獨無害，
組合起來可能只符合少數幾個人。

## 核心心態（重要）

這是公認的開放問題（arXiv 2026 論文實測八種技術，隱含身分洩漏率仍達 95%）。
預設目標仍是「偵測並警示，讓使用者自己判斷」，不是宣稱能完全自動解決。
進階的自動降階必須由使用者明確啟用，而且要以最少資訊損失達到策略門檻；
`off` 永遠保留原本只提示的行為。

## 準識別子（quasi-identifiers）

單獨無害、但組合能定位的屬性，至少涵蓋：

- 年齡 / 年齡範圍
- 地區（縣市、區、園區等）
- 職業 / 職稱
- 性別
- 服務公司 / 機構
- 其他可延伸：學歷、婚姻狀態、特殊經歷

## 風險估算

- 簡化版（第一優先）：計算一段文字裡同時出現幾個準識別子，
  共現越多、風險越高（規則式計分即可）
- 進階版（已完成第一階段）：使用內政部「人口數單一年齡組─按性別、區域別分」
  的離線彙整快照，對年齡／性別／縣市中至少兩個可解析維度，查詢官方交叉統計人數。
  結果是「符合已涵蓋條件的人口上限」，不是正式的 k-anonymity 保證；職稱、公司、
  區級地址等尚未納入的條件，可能讓實際符合人數更少。無法估算時保留簡化版評分。

## 輸出格式

不強行遮蔽，而是輸出風險等級 + 建議泛化。範例：

```
⚠️ 組合風險：高
   偵測到：年齡(32) + 地區(新竹) + 職業(記憶體測試工程師)
   估計符合人數 < 100 人
   建議泛化為「30-35歲」「北部」「半導體業」
```

輸出應包含：

- `risk_level`（高/中/低）
- `contributing_types`（哪些準識別子造成風險）
- 建議的泛化方式（把精確值換成範圍）
- `population_estimate`（選填；官方交叉統計的人口上限、涵蓋／未涵蓋型別、
  資料月份，以及逐一放寬年齡／性別／地區後的人口變化）

## 人口統計估算的安全邊界

- 只使用彙整後的官方人口數，不含個人層級資料。
- 執行時只讀取 repo 內快照，不把待分析文字送往統計網站。
- 只有文字明確寫出歲數時才查單一年齡；民國年次／出生年會受生日影響，不當成精確年齡。
- 地址必須由 Layer 2 的 `ADDRESS` span 解析出唯一縣市；多個縣市或無法判定時不估算。
- 職業統計尚未納入，避免把不同來源的邊際比例相乘並誤稱為真實交叉人數。

## 自動風險降階（opt-in）

`PII_RISK_REDUCTION_POLICY` 支援四種策略：

- `off`（預設）：只提示，不額外修改準識別子。
- `permissive`：只在殘餘分數達 0.60 時處理，直到低於高風險門檻。
- `balanced`：處理到低於 0.30，優先移除性別、再遮蔽公司，盡量保留職稱。
- `strict`：處理所有已辨識的準識別子。

公司、職稱、地址等已有 span 的型別使用既有 MappingTable 佔位符，因此回程可
還原；年齡與性別沒有 detector span，改成「成年年齡層」「人士」等粗粒度文字。
策略只針對系統已辨識到的內容，不得把 `score = 0` 解讀為客觀的零風險。

## 與其他模組的介面

- Layer 3 的結果對應 `detect_all` 頂層的 `combination_risk` 欄位
  （`score` + `contributing_types`，屬選填欄位）
- 與 Layer 1/2 的偵測獨立：Layer 1/2 抓「明確的個資」，
  Layer 3 抓「組合起來的風險」，兩者不重疊
- 第一版不接載體的自動遮蔽，先做成可獨立呼叫、輸出警示的模組
